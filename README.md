# Бот контроля чатов менеджеров Hickmet

Бот каждые 1,5 минуты забирает из Битрикс24 переписки открытых линий (WhatsApp через Wazzup), считает те же показатели, что в отчете за май–сентябрь, и пишет в Telegram.

## Быстрый старт

```bash
cp env.example.txt env.txt            # вебхук Битрикс24 и токен Telegram
cp names.example.txt names.txt        # варианты написания имен менеджеров
cp schedule.example.txt schedule.txt  # смены менеджеров по дням недели
python3 probe.py                      # проверить вебхук и права
python3 tg_setup.py                   # подключить Telegram-бота
python3 main.py --once --dry-run --report   # один цикл без отправки
python3 main.py                       # постоянная работа
```

Нужен только Python 3.10+, сторонние библиотеки не используются.

**Файлы настройки** лежат рядом с `main.py` и в git не попадают:

| Файл | Что в нем |
|---|---|
| `env.txt` | вебхук Битрикс24, токен Telegram, chat id руководителя, режимы `TEST_MODE`, `ALERTS` |
| `names.txt` | `вариант = каноническое имя`, строки `! Имя` исключают пользователя из менеджеров |
| `schedule.txt` | `Имя; пн; вт; ср; чт; пт; сб; вс`, часы `09-18` или `-` для выходного |
| `*.sqlite` | база с перепиской, создается сама |

## Что он делает

| Когда | Кому | Что |
|---|---|---|
| Клиент ждет ответа 15+ мин рабочего времени | менеджеру (или руководителю, если у менеджера нет Telegram) | ссылка на чат, сколько ждет, тема |
| Раз в час, если кто-то ждет 60+ мин | руководителю | список таких чатов по менеджерам |
| 10:05 | руководителю | ночные обращения без ответа, сколько follow-up нужно сделать |
| 10:05 | каждому менеджеру | его список клиентов для follow-up со ссылками |
| 19:30 | руководителю | итоги дня: новые обращения, первый ответ, кто ждет, follow-up, образцовые диалоги, таблица по менеджерам |

Правила те же, что в отчете:
- менеджер = автор исходящего сообщения, поле «ответственный» не используется;
- технические пользователи и администратор вебхука исключены (names.txt);
- казахский и русский разбираются одинаково;
- приветствие и «менеджер напишет» не считаются ответом.

## Что нужно, чтобы запустить

1. **Вебхук с правами** `imopenlines`, `im`, `crm`, `user`. Его должен создать администратор или руководитель открытых линий. Иначе вебхук видит только свои чаты.
2. **Сервер, который работает круглосуточно.** Подойдет VPS за 5–7 USD в месяц, например ps.kz или Hetzner, с Python 3.10+. Дополнительные библиотеки не нужны.
3. **Telegram-бот.** Создайте его через @BotFather и получите токен. Нужен чат руководителя и, по желанию, личные чаты менеджеров. Каждый менеджер один раз пишет боту /start.
4. **ID открытых линий Алматы.** Их покажет `probe.py`. Астану не включаем.
5. **Решения от вас:**
   - рабочие дни и часы (сейчас 10:00–19:00 без выходных);
   - пороги алертов (15 и 60 минут);
   - кто получает отчеты.

## Источник переписки (с 15.10.2026)

Открытая линия Битрикс24 отключена. Wazzup пишет каждое сообщение комментарием в ленту сделки, и бот по умолчанию читает эти комментарии через вебхук Битрикс24 (`SOURCE=comments`). Ничего дополнительно настраивать не нужно.

Запасной вариант: принимать сообщения прямо от Wazzup через вебхуки (`SOURCE=wazzup`). Он нужен, только если вебхук Wazzup освободится или его будут дублировать боту.

1. В личном кабинете Wazzup получите **API-ключ** и впишите в `env.txt`:
   ```
   WAZZUP_API_KEY=ваш_ключ
   WAZZUP_WEBHOOK_PATH=придумайте-длинное-случайное-слово
   WEBHOOK_PORT=8080
   ```
2. Запустите бота на сервере: `python3 main.py`. Он слушает порт 8080.
3. Адрес для Wazzup должен быть https. Проще всего поставить перед ботом Caddy, он сам выпустит сертификат.
4. Подключите вебхук: `python3 wazzup_setup.py https://ваш-домен/придумайте-длинное-случайное-слово`.
   Скрипт сначала покажет текущий адрес вебхуков. Если там уже стоит адрес другой системы, он ничего не заменит без `--force`.

Wazzup не отдает старую переписку, поэтому бот видит сообщения с момента подключения. Отчет за день станет полным на следующий день, follow-up — через 1–2 дня.

## Запуск

```bash
# откройте env.txt и впишите вебхук, токен Telegram, чаты
python probe.py           # проверка вебхука и прав; вывод прислать для настройки
python main.py --once --dry-run   # один цикл, сообщения печатаются, а не отправляются
python main.py            # постоянная работа (через systemd или screen)
```

Проверка логики на старой выгрузке, без Битрикс:

```bash
python replay.py ../m1.pkl 2026-09-24
```

## Как устроено

- `bot/collector.py`: сбор из Битрикс24. Берет сессии открытых линий (`crm.activity.list`), находит их чаты (`imopenlines.dialog.get`) и забирает всю историю чата (`im.dialog.messages.get`, при первой загрузке за `HISTORY_DAYS` дней, по умолчанию 30).
- `bot/parse.py`: определяет, кто автор сообщения. Сообщения, отправленные с телефона, Wazzup пересылает с заголовком «Исходящее сообщение, автор: …». Если вместо имени стоит «Телефон», автор неизвестен.
- `bot/analytics.py`: состояние диалога. Первый ответ, ждет ли клиент, нужен ли follow-up, потребности клиента и закрыты ли они.
- `bot/engine.py`, `bot/reports.py`: алерты и отчеты.
- `bot/store.py`: база SQLite на сервере.

## Важно

- **Ключ вебхука** в адресе дает доступ к данным портала. Храните его только в `env.txt`, не пересылайте в чаты. После настройки ключ лучше перевыпустить.
- **Тексты переписок** хранятся только на вашем сервере. В Telegram уходят ссылки на чаты и темы, а не тексты клиентов.
- **Сообщения с телефона.** Если менеджер пишет с телефона и Wazzup ставит автора «Телефон», бот не знает, кто ответил. Доля таких сообщений есть в вечернем отчете. Просьба к менеджерам: отвечать из Битрикс24.

## Тестовый Telegram-бот (16.10.2026)

1. В Telegram: @BotFather → /newbot → токен. Впишите в env.txt строку `TG_TOKEN=...` (токен никому не пересылайте).
2. `python3 tg_setup.py` и напишите боту /start: скрипт запишет ваш chat id в env.txt (`TG_SUPERVISOR_CHAT`).
3. `python3 main.py` (без --dry-run). Пока работает, бот отвечает на команды:
   /report (общий отчет, `/report вчера`), /managers (кнопки с менеджерами), `/m Имя` (карточка менеджера), /all (все сразу).
   По расписанию: 10:05 утренняя сводка, 19:30 общий отчет и карточки всех менеджеров.

`TEST_MODE=1` (по умолчанию): все уходит только в TG_SUPERVISOR_CHAT, менеджерам ничего. `ALERTS=0` (по умолчанию):
алерты «клиент ждет» выключены, пока Wazzup теряет незавершенные диалоги. Команды принимаются только от
TG_SUPERVISOR_CHAT и TG_ALLOWED_CHATS; чужим бот отвечает «доступа нет».

## График, доступы, разборы (16.10.2026)

**График** в `schedule.txt` (пн; вт; ...; вс, часы или «-» для выходного). Скорость ответа и ожидание клиента считаются
по смене того менеджера, кто отвечает или ведет чат. Кого нет в графике, считаем по WORK_START–WORK_END (09–18).
В общем отчете отдельно видно, сколько клиентов ждут у менеджеров, которые сегодня на выходном.

**Доступы.** Человек пишет боту, админу приходит заявка с кнопками: какой это менеджер, «Админ» или «Отклонить».
Менеджер видит только себя: /me (карточка), /razbor (разбор диалогов), с «вчера». Админ: /report, /managers
(карточка + кнопка «Разбор диалогов»), /m, /razbor Имя, /all, /access (список и «Убрать доступ»).

**Разбор** диалогов менеджера за день: итог, три главных совета, по каждой сделке замечания (медленный первый ответ,
цена не названа, не закрытые вопросы, клиент ждет, обещали уточнить, нужен follow-up). Тексты клиентов не используются.
При TEST_MODE=0 менеджер получает разбор сам через 10 минут после конца своей смены.
